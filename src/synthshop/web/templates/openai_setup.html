Set up OpenAI

{{ 'Key configured in this running app' if ready.vision else 'No key configured in this running app' }}

Readiness checks presence only, not authentication, account credit or model access. Setup does not contact OpenAI or spend money.

  1. Save any draft edits. In the terminal running your normal SynthShop app, press Ctrl-C to stop it. Your saved drafts and photos remain local.

  2. Create or copy an API key from OpenAI API keys. API billing is separate from a ChatGPT subscription.

  3. In that same terminal and directory, with the same Python environment activated, run this command without adding your key:

    synthshop setup-openai

    Confirm the displayed destination. Paste the key only at the terminal's hidden prompt, then press Enter. Nothing appears while you paste. Empty input or Ctrl-C cancels. Replacing an existing OpenAI key needs confirmation.

    The command saves only the OpenAI entry in the launch directory's .env, with owner-only file permissions; other settings stay intact. Never enter credentials in this browser, chat, command arguments or source control.

  4. Restart from the same directory using synthshop serve with your usual options (such as --port and --data-dir). Open the new unlock link printed by that launcher; this old browser session cannot unlock the restarted app.

  5. Backend readiness should now show vision Configured. Only choose Analyze when you want to send the item's photos to OpenAI; analysis may incur API charges. A configured badge does not prove the key works.

Still not configured?

The app reads .env from the directory where you launch it, not from --data-dir. Restart after saving; refreshing this old process does not reload credentials. A process-level OPENAI_API_KEY overrides .env; setup refuses to save while that override is set. Remove it in your normal launch terminal before rerunning setup.

Offline / test launcher? A publishing-validation app may deliberately use a fresh HOME/environment, fake Reverb/R2 clients and no vision key, or ignore .env. Do not put real credentials in that fixture or enable its real providers. Follow these steps only in your normal app environment. Test badges are not real-account readiness.

Manual identification and editing remain available without a key.
